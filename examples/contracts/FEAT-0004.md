# CONTRACT: Verificación en Capas, Reparación Automática, Métricas y Servidor MCP (AC/DC Layer)
# ID: FEAT-0004
# Status: RESOLVED
# Mode: LOOP
# Gate-Mode: STRICT

## Intent
Implementar la arquitectura de verificación en capas (AC/DC Layer), el agente de reparación rápida (Solve), el motor de métricas de First-Pass Quality, la auditoría de trazabilidad de especificaciones y la implementación ejecutable del Servidor MCP para SDD-GL.

## Use Case
**Actor:** Desarrollador solitario usando SDD-GL (en Claude Code, Antigravity, Cursor, Windsurf o VS Code).
**Goal:** Disponer de un ciclo de desarrollo autónomo multicapa, con autorreparación acotada, métricas de calidad y herramientas MCP nativas.

### Main Flow
1. El desarrollador aprueba el contrato (Status: APPROVED, Mode: LOOP).
2. El Loop ejecuta la suite funcional (unit, integration, assertions).
3. El Loop ejecuta las verificaciones adicionales en capas:
   - Capa 1: Análisis Estático y Tipado Estricto (`static`).
   - Capa 2: Escaneo de Seguridad y Vulnerabilidades (`security`).
   - Capa 3: Guardrail Arquitectónico basado en CONSTITUTION.md / stack.md (`arch`).
4. Si una verificación falla con un hallazgo acotado, el agente Solve aplica una corrección localizada (≤ 3 reintentos).
5. El Loop re-ejecuta únicamente la capa afectada y actualiza el Completion Map plano.
6. Al completarse todas las capas, se actualizan las métricas en `.sdd/metrics.json`.
7. El desarrollador consulta métricas con `/sdd-metrics` o audita trazabilidad con `/sdd-audit` (o vía herramientas MCP).

### Alternative Flows
- AF-01: Verificación falla por ambigüedad o decisión de diseño → Loop detiene ejecución, registra en Ambiguity Log y escala a Gate.
- AF-02: El agente Solve agota sus 3 reintentos sin éxito → el ítem se marca como BLOCKED y escala a Gate.
- AF-03: `/sdd-audit` detecta orphan specs o código de dominio sin contrato → genera reporte estructurado no bloqueante.

## Business Rules
- BR-001: El Completion Map debe soportar formato plano de una línea por verificación: `[item-id]|[layer]|[test-id]|[agent]|[status]`.
- BR-002: Las 4 capas de verificación estándar son: `functional`, `static`, `security` y `arch`.
- BR-003: El agente Solve solo puede corregir hallazgos sintácticos, linting, imports, tipado y desajustes menores de assertions; tiene estrictamente prohibido alterar interfaces públicas o reglas de negocio.
- BR-004: El agente Solve tiene un límite estricto de 3 intentos por hallazgo antes de declarar BLOCKED y escalar a Gate.
- BR-005: Las métricas de First-Pass Quality Rate se calculan y persisten en `.sdd/metrics.json` diferenciando FEAT vs FIX.
- BR-006: La Constitución (`CONSTITUTION.md`) es opcional; si no existe, los agentes usan `stack.md` o el preset cargado en `presets/`.
- BR-007: El servidor MCP debe implementar y exportar los endpoints ejecutables JSON-RPC para todas las operaciones del framework.

## Acceptance Criteria
- AC-001: GIVEN un contrato aprobado WHEN el Loop inicia THEN el Completion Map despliega las capas correspondientes por ítem de forma tabular plana.
- AC-002: GIVEN un error de lint o tipado WHEN el agente Solve interviene THEN el hallazgo se repara en ≤3 intentos y la capa pasa a ✅.
- AC-003: GIVEN un fallo irresoluble automáticamente WHEN Solve falla 3 veces THEN el contrato transiciona a DRAFT/GATE con registro en Ambiguity Log.
- AC-004: GIVEN contratos resueltos en el repositorio WHEN se ejecuta `/sdd-metrics` (o `sdd_get_metrics`) THEN se muestran el First-Pass Rate por tipo, el promedio de reintentos y el ratio de escalados.
- AC-005: GIVEN especificaciones sin tests o código de dominio sin contrato WHEN se ejecuta `/sdd-audit` (o `sdd_audit_traceability`) THEN se genera el reporte de trazabilidad y cobertura.
- AC-006: GIVEN un cliente MCP (Cursor/Windsurf/Claude) WHEN se conecta al servidor `@sdd-gl/mcp-server` THEN todas las herramientas responden según el protocolo estándar.
