# CONTRACT: Living Visual Dashboard & GitHub Pages Telemetry Generator
# ID: FEAT-0005
# Status: RESOLVED
# Mode: LOOP
# Gate-Mode: STRICT

## Intent
Implementar un generador de Dashboard HTML interactivo, visual y publicable en GitHub Pages (`docs/index.html`), que procese y presente en tiempo real las métricas de desarrollo pasadas, presentes y futuras, el estado de los contratos, la matriz de verificación en 4 capas (AC/DC) y la trazabilidad del código sin requerir lectura de texto plano línea por línea.

## Use Case
**Actor:** Desarrollador o visitante del repositorio GitHub de SDD-GL.
**Goal:** Consultar de forma gráfica, condensada e interactiva la salud, evolución histórica, estado de contratos y métricas de entrega del framework.

### Main Flow
1. El generador (`mcp/dashboard-gen.js`) recopila los datos de `contracts/*.md`, `.sdd/metrics.json`, `.sdd/runs/` y el sandbox de pruebas.
2. El generador compila la telemetría viva y actualiza el archivo standalone `docs/index.html`.
3. El usuario puede abrir `docs/index.html` localmente o visitarlo en `https://charlyzeta.github.io/SDD-GL/`.
4. El dashboard renderiza gráficos interactivos:
   - Medidor de First-Pass Quality Rate (FPQR).
   - Matriz de capas de verificación (Functional, Static, Security, Architecture).
   - Línea temporal (Pasado: evolución de versiones; Presente: contratos activos; Futuro: roadmap interactivo).
   - Explorador interactivo de contratos con vista detallada del Completion Map en tiempo real.
5. El Loop ejecuta la regeneración automática de `docs/index.html` tras cada resolución de contrato.
6. El desarrollador puede invocar la regeneración manual con `/sdd-dashboard` o vía MCP con `sdd_generate_dashboard`.

### Alternative Flows
- AF-01: No existen archivos en `.sdd/runs/` o `.sdd/metrics.json` → el generador infiere métricas a partir de los contratos en `contracts/` sin fallar.
- AF-02: Se invoca `/sdd-dashboard` en local → el generador actualiza `docs/index.html` y abre la URL local en el navegador predeterminado.

## Business Rules
- BR-001: El Dashboard HTML generado debe ser 100% standalone (un único archivo `docs/index.html` autocontenido con estilos y scripts CDN) para funcionar en GitHub Pages sin dependencias de servidor.
- BR-002: Debe cuantificar visualmente el First-Pass Quality Rate (FPQR), promedio de reintentos por contrato y tasa de escalado a Gate.
- BR-003: Debe reflejar el estado vivo de todas las capas de verificación (`functional`, `static`, `security`, `arch`) y el total de tests automatizados.
- BR-004: Debe incluir una vista temporal dividida en Pasado (historial de versiones), Presente (contratos en curso) y Futuro (roadmap de hitos).
- BR-005: El servidor MCP debe exponer la herramienta `sdd_generate_dashboard` para integración continua en IDEs.
- BR-006: La resolución de cualquier contrato en el Loop debe disparar la sincronización de `docs/index.html`.

## Acceptance Criteria
- AC-001: GIVEN el repositorio con contratos resueltos WHEN se ejecuta `mcp/dashboard-gen.js` THEN se genera `docs/index.html` con todos los contratos, capas y métricas actualizadas.
- AC-002: GIVEN el archivo `docs/index.html` WHEN se carga en un navegador web THEN renderiza los gráficos de First-Pass Quality, matriz de capas y línea temporal sin errores de JavaScript.
- AC-003: GIVEN un cliente MCP WHEN llama a `sdd_generate_dashboard` THEN el servidor regenera el archivo HTML y devuelve la ruta y estadísticas.
- AC-004: GIVEN un usuario de Claude Code o Antigravity WHEN ejecuta `/sdd-dashboard` THEN el sistema regenera el dashboard y confirma el enlace de visualización.
- AC-005: GIVEN el modo Loop WHEN un contrato pasa a `RESOLVED` THEN el dashboard se actualiza automáticamente en disco.

## Entities Affected
- `docs/index.html`: Dashboard visual standalone publicado para GitHub Pages.
- `mcp/dashboard-gen.js`: Motor autónomo de extracción de datos y renderizado HTML.
- `mcp/server.js`: Expone herramienta `sdd_generate_dashboard`.
- `.agents/skills/sdd-dashboard/SKILL.md`: Habilidad para Antigravity CLI e IDE.
- `.claude/commands/sdd-dashboard.md`: Comando para Claude Code.
- `protocol/loop.md`: Hook de actualización al completar contratos.
